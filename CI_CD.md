## Overview

NchantdOffice is a Qt-based GUI application. Its validation
pipeline focuses on headless smoke tests (does the GUI launch
under `QT_QPA_PLATFORM=offscreen`?), the non-Qt pytest subset,
and the sasquatch auditor — rather than a full hosted CI matrix.

## Pipeline Stages

1. **Lint & Format** — `ruff check .` (replaces black per
   T-NEW-110). Black is no longer a project dependency.
2. **Smoke Tests** — `QT_QPA_PLATFORM=offscreen python -m
   nchantdoffice --version` (xvfb-equivalent for Qt6 on Linux).
3. **Unit Tests** — `pytest tests/` with `--continue-on-collection-
   errors` set (per `pytest.ini`). The aspirational script tests
   under T-NEW-120 (5 RED) are the next acceptance gate.
4. **Security Audit** — `sasquatch analyze -p . --skip-pii-secrets`.
   Output: `PROJECT_TRACKER.yaml` (full audit) + `FALCON_TEST.yaml`
   (test-run summary).
5. **Build** — `python -m build` (or `pip wheel .`) for sdist +
   wheel. Cross-platform: Linux .deb/.rpm/.AppImage, macOS .dmg,
   Windows .exe via PyInstaller.
6. **Sign** — GPG sign the wheel/sdist for distribution.

## Local Validation

```bash
# Run smoke test (headless Qt6)
QT_QPA_PLATFORM=offscreen python -m nchantdoffice --version

# Run the non-Qt pytest subset
QT_QPA_PLATFORM=offscreen /home/solubrew/ENVs/sasquatch/bin/python \
  -m pytest tests/ --continue-on-collection-errors -q

# Lint
ruff check .

# Audit
sasquatch analyze -p . --skip-pii-secrets

# Build wheel
python -m build
```

The `ENVs/sasquatch` venv is the canonical test env (per
`TODOs.md` §1). Use it for any local validation that needs the
internal-project stack (`nchantrs`, `pyffice`, `kahndor`,
`pycurity`, `subtrix`, `squirl`, `micromole`) available.

## CI Configuration

The committed `.github/workflows/ci.yml` and `.github/workflows/
docs.yml` define the intended hosted-CI contract:

- **Linux runner**: `QT_QPA_PLATFORM=offscreen xvfb-run pytest`,
  `ruff check`, `sasquatch analyze`.
- **macOS runner**: native `pytest` (no xvfb needed).
- **Windows runner**: native `pytest` (PySide6 wheels have Qt6
  pre-bundled).
- **Docs deployment**: `docs.yml` builds mkdocs on push to
  `gamma` and publishes to the project docs site.

**Status:** the workflows are committed but inactive (no remote
CI host is wired up). Run them locally per "Local Validation"
above until a hosted runner is provisioned.

## Secrets

- All secrets stored in PyKeyStore (encrypted at rest).
- No environment variables used for credentials.
- The PyKeyStore passphrase prompt is deliberate (TTY-bound at
  runtime; non-TTY raises `EOFError` correctly per the working
  agreement).
- For non-TTY deploys, set `PYKEY_PASSPHRASE` env var to bypass
  the prompt (this is the only env-var bypass path; do not use
  for credentials).

## Audit artifacts

- **`PROJECT_TRACKER.yaml`** — full sasquatch audit (every
  dimension, every issue). Regenerated by
  `sasquatch analyze -p .`.
- **`FALCON_TEST.yaml`** — test-run summary (duration, status,
  pass/fail/skip counts). Regenerated by the pytest-falcon
  runner.
- Both are committed so reviewers can see the current state
  without re-running the audit locally.
